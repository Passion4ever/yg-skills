# grill-me

> 这一类技能的五段骨架、为什么这么定，见 [`../README.md`](../README.md)。约定由 `tests/test_common_ground.py` 强制。

把一个还没想清楚的思路、计划或实验设计**问清楚**。激活期间只提问，一个字的方案都不写，直到每个含糊的地方都被逼出明确答案。

## 它不做什么

- **不给方案、不写代码、不做分析**——在用户说「可以了」之前，产出为零
- **不替用户拍板**——环境里查得到的事实自己查，需要人定的选择只问不答
- **不按清单走**——没有固定问题列表，每一轮重新判断哪里最含糊、错了代价最大
- **不比谁问得多**——三个问题够就三个，五十个才够就五十个

## 手动触发

这个技能带 `disable-model-invocation: true`，**只能敲 `/grill-me` 调用**，模型不会自己启动它。

两个原因：

1. 它会**完全接管对话**。误触发的代价是用户想要个答案，却挨了一轮盘问。
2. 它和 `superpowers:brainstorming` 管的是同一段地盘（动手前把需求问清楚）。保持手动，两者就不会抢。

**推论**：description 里不要再写「当用户说 X 时立刻使用」那种触发词——模型看不到它，写了也不会生效，只会让人误以为它能自动启动。

## 用法

想清楚之前敲 `/grill-me`，然后回答问题。随时可以喊停（「够了」「先这样」「总结一下」）。

一轮 1～5 个问题，编号，问完停下等回答。超过 5 个说明把前置还没定的问题也塞进来了。

## 收尾格式

用户喊停、或者判断问完了，固定输出三节：

| 节 | 内容 |
|---|---|
| ① 定下来了 | 编号，一条一个决定，写成结论句 |
| ② 还悬着 | 每条注明是**没问到**，还是**问了但用户没定** |
| ③ 下一步 | 一句话 |

这份总结是整场拷问唯一留下来的东西——写到能直接复制去开新会话的程度。**总结之后仍然不动手**，等用户说开始。

## 完成条件

不是「问够了多少个」，是**没有任何东西是被默默假设的**：每个分支都访问过，每个含糊处都有明确答案。
