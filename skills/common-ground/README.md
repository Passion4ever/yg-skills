# common-ground

**别的技能产出东西，这一类产出共识。**

一个在动手**前**把共识建起来（`grill-me`），一个在跑偏**后**把共识修回去（`catch-me-up`）。分类名取自 Herbert Clark 讲对话的 common ground：双方建立共同基础叫 grounding，跑偏后拉回来叫 repair——正好是这一对。

| | grill-me | catch-me-up |
|---|---|---|
| 谁触发 | 用户手敲 `/grill-me` | 用户喊停，或模型读到困惑信号自己启动 |
| 时机 | 动手**前** | 动手**中** |
| 作用对象 | 用户脑子里还没想清楚的想法 | 模型已经做过、但没交代的事 |
| 激活期间 | 禁止产出 | 禁止产出 |

## 五段骨架

这一类技能的价值全在**多次调用行为一致、输出标准化**。保证一致性的手段是固定骨架：

```markdown
# <中文名>

**成功标准**：<一句可判定的话。判据在用户身上，不在格式上>
激活期间**不做**：<清单>

## 怎么做        <约束条目，每条都必须改变输出>
## 输出格式      <字面骨架，照抄再填>
## 完成条件      <由用户判定，不是自己宣布>
```

**约定钉在 `tests/test_common_ground.py`，不在这份 README 里。** 文档会和现实走岔，走岔之后变成误导；测试走岔会直接红。加第三个技能时，缺哪一段那里会告诉你。这份 README 只负责讲为什么。

## 四条设计原则

**一、能删的都删。** 判据不是「短」，是**一句话删掉之后输出会不会变**。不会变就删。`grill-me` 原来有一节「问什么」，列了六个切入角度（目标/边界/前提/替代/失败/代价）——那是灵感提示不是约束，删了技能照样跑，留着每次调用问的方向还会随机漂。**它本身就是不一致的来源。**

**二、输出格式写成字面骨架，不写成散文。** 「先写一句话概括，然后列出已完成的事项」这种描述会被重新组织，带 `<占位符>` 的骨架会被照抄。测试用占位符数量当判据，就是防止这一节退回成描述。

**三、凡是分类分档的地方用封闭词表。** `catch-me-up` 的「你定的 / **我定的**」、`grill-me` 的「没问到 / 问了但用户没定」——二选一，不是自由发挥。同一招在 `sci-read-paper` 里用了 6 处。

**四、✗ 和 ✓ 只成对出现，且放在照抄区之外。** 单独一个 ✗ 是禁令，只说了别做什么、没给正确形状；当失败模式是「照做了但输出形状不对」时，禁令会被讨价还价，正面配方不会——成对才是配方。位置也要紧：骨架是逐字照抄的，例子写进 `---` 里面，模型会连例子一起抄进输出。两条都由测试挡着。

选点只挑**照着规则做、结果还是错、而且错得看不出来**的地方。`catch-me-up` 的「① 一句话不许有专有名词」就是典型：写成「用 LightningCLI 重构 config 的继承链」完全符合字数和格式，只是用户还是没看懂——这种错文字说不清，一个例子就说清了。

还有一个跨技能的共同手法：**在最容易被糊弄的那一段旁边写一句自检**。`catch-me-up` 的「④ 全是『你定的』是可疑信号」、`grill-me` 的「② 空着是可疑信号」——因为这两处只要偷懒就会产生一份好看但空洞的输出。

## 骨架为什么必须内联在 SKILL.md

`references/` 和 `assets/` 是**按需读**的——模型得先决定去读它，那个「决定」就是一次抛硬币。把每次调用都必用的骨架放进按需加载的文件，等于亲手引入不一致。更隐蔽的是模型读了之后往往**转述**而不是照抄，中间隔一道，格式就开始漂。

判据是「每次调用是不是都要用」：

| 情况 | 放哪 |
|---|---|
| 每次都要照抄，且短 | **SKILL.md 内联** |
| 只有某个分支才用到 | `references/` |
| 体积大、由脚本生成、或产出的是文件而不是对话 | `assets/` |

对比 `sci-read-paper`：它的骨架在 `assets/report-template.html`，因为那是 35 个占位符的整页 HTML，而且模型根本不打它——`new_report.py` 生成文件，模型往文件里填。产出物是文件。common-ground 这两个技能的产出物就是聊天框里的文字，`assets/` 在这儿没有消费者。所以测试禁止 `references/` 和 `assets/`。

`agents/openai.yaml` 不在此列——那是 Codex 的显示名，模型从头到尾不读它，搬不走任何骨架。禁的是**按需加载的内容**，不是子目录本身。

## 装

按技能逐个软链，`~/.claude/skills/` 是平铺的，不认这层分类目录：

```bash
ln -s "$PWD/grill-me"    ~/.claude/skills/grill-me
ln -s "$PWD/catch-me-up" ~/.claude/skills/catch-me-up
```

这两个不加 `sci-` 那样的前缀——前缀是防止在 `~/.claude/skills/` 那个全局平铺命名空间里撞名，按需加，不是必须统一的规矩。这俩名字本身够独特。
