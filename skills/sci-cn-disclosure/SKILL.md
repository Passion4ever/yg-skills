# 中国发明专利技术交底书

交底书是给专利代理师的内部材料,申请文件由他据此撰写,**因此没有法定格式要求**——权项标点、说明书不得插图、摘要 300 字上限、页边距一概不适用,套用只会把交底书写窄。

**文中的清单都是例示,不是穷举**——举例偏算法与生物序列,那只是最初的使用场景,不是适用边界。清单没覆盖的情形,回到它前面那句规则去推,别因为"清单里没有"就跳过。

## 铁律

1. **绝不编造。** 文献、专利号、URL、实验数据、替代方案,一概不许。**搜到号码不等于核实过**——没打开看过原文的,按"搜不到"处理:留白,记进 `QUESTIONS`。
2. **按证据强度序位取数**(实测 > 代码 > 论文 > 口述),用可得的最强级,**不得把来源说得比实际强**。每处不一致都要报告发明人。
3. **主张范围不得超出证据覆盖的范围。** 某一层面的实验只支持该层面的结论,不得外推到未验证的层面。
4. **同一概念全文只用一个规范中文术语**,权利要求、说明书、附图三处一致。
5. **不要反射性地添加系统权项、用途权项。** 存储介质与电子设备是计算机实施方法的常规配套,可以加;再多就需要理由。

交付时必须成立的**可核验条件**不在这里,在 `CONTRACT`。

## 常量

- `TEMPLATE = references/template-disclosure.md` —— 交底书的结构外壳与撰写惯例
- `DISCIPLINE = references/alternatives-discipline.md` —— 可替代实施方式的举证纪律
- `CONTRACT = references/delivery-contract.md` —— 交付契约:唯一的合格判据
- `LEDGER_EVIDENCE = evidence.json` —— 权项特征 → 源证据
- `LEDGER_ALTERNATIVES = alternatives.json` —— 具体选择 → 替代方案 + 依据
- `REVIEWER_MODEL` —— 外部审查员评审用的模型,推理强度 `high`。**这里要的是性质,不是型号:与起草的模型不是同一个**,独立性才是这一步的意义。当前取 `gpt-5.6-sol`,经 Codex MCP 调用;型号过期就换,实际用了哪个记进 `metadata.assurance.external_review.model`
- `QUESTIONS = evidence.json 的 inventor_questions 数组` —— 该问发明人而当下无人可答的问题
- `FIGURES = figures/`(spec 放 `figures/specs/`) —— 附图与其源
- `AUTO_PROCEED = false` —— **遇到该问的就停下来问用户**,保护范围是发明人的决定,不要自行替他拍板。只有当本次运行确实没有人可问时(如无人值守的子代理或批处理),才退而把问题原样写进 `QUESTIONS` 并继续——问题可以悬而未决,不可以消失。这是退路,不是省事的默认:能问就问

## 证据强度序位

| 级 | 来源 | ID 前缀 |
|---|---|---|
| 1 | 实测、原始结果文件、运行产物 | `C###` |
| 2 | 源代码 | `C###` |
| 3 | 论文稿、技术报告、实验记录 | `P###` |
| 4 | 发明人口述 | `P###`,须在 `note` 注明"发明人口述,未见书面记载" |

公式 `E###`,附图 `F###`,均带 `file:line` 或章节定位。

**材料很少齐全**,只有论文、或只有代码没有论文,都常见。只有论文时论文就是来源,写 `explicit` 没问题——问题只在于假装它经过了实测核对。**缺料不是拒绝撰写的理由,是降低声称强度的理由。**

## 工作流

每个阶段都有固定的**产物**与**门禁**。**门禁没过就停在那一阶段**——后一阶段不得默默替前一阶段补漏,带着问题往下走一步,回头改的代价就翻一倍。

### 阶段 0 —— 信息采集

表头字段见 `TEMPLATE` 第一节,逐项填。

记录**公开状态**——时间、地点、形式,论文、预印本、学位论文、代码仓库、会议报告、产品发布都要记。即便发明人已决定照常申请,也要如实写明:代理师需要这个事实来评估新颖性风险、决定申请策略。**向自己的代理人隐瞒,和决定照常申请,是两回事。**

已经公开过的,**还要写清这个公开在法律上意味着什么**——不是给结论,是把代理师需要的事实摆齐:

- 公开日距今多久,与**六个月**宽限期的关系
- 该公开形式**是否落入**第 24 条的三种例外(中国政府主办或承认的国际展览会首次展出 / 规定的学术会议或技术会议首次发表 / 他人未经同意泄露)。**期刊论文、预印本、公开代码仓库都不在这三种之内**——这一条最常被误以为可以适用
- 是否还有别的公开渠道(实验室主页、结题报告、答辩、投稿平台的公开评审)

**"这值不值得申请"不是本技能的判断**,那要专业检索与代理师的意见。但上面这些是可核查的事实,发明人往往并不知道,而**代理师需要提前量**——公开状态这一节写空,他就得回过头来问,一来一回耽误的正是最不该耽误的时间。

未知事实标 `[待确认:具体问题]`。

#### 先查这个发明有没有被申请过

**这是全流程的第一件事,写任何一个字之前就要做完。** 如果同一发明已有在先申请,后面所有工作的前提都变了——该做的不是重新划保护范围,而是把已授权的权利要求调出来,看它覆盖到哪儿、还剩什么没覆盖。

**它跟阶段 4 的检索不是一回事。** 阶段 4 找的是**别人的**同方向专利,用来写背景技术;这里找的是**自己人的**在先申请。检索式也不同——不要用技术关键词,用**人和机构**:

1. **发明人姓名**(中文与拼音都试),尤其论文的通讯作者与第一作者
2. **申请人机构全称**,配技术主题词
3. **技术主题词**本身,时间窗放宽到论文投稿日前两年

找到的,把**公开号、授权公告号、申请日、授权公告日、权利要求 1 的技术主题**都记进 `evidence.json` 的 `metadata.prior_filings`,并**打开权利要求 1 原文**看它实际覆盖什么——不要只看标题。没找到的,把**检索式与检索到的库**记进同一个字段,写明"未检索到"。

**为什么必须单列一步:能想起来查的人很少。** 八次实测运行里只有一次想到去查,而那一次查出来:同一批发明人、同一所大学,申请日比论文出版早 15 天,并且已经授权。其余七次都在为一个已经拿到专利的方案重新写交底书。这个信息读多少遍论文和代码都不会出现,**只有主动去查才有**。

同样守边界:**在先申请覆盖到什么程度、还值不值得申请,不是本技能的判断**,那要代理师看权利要求。本技能只负责把这件事查出来、摆到桌面上。

**产物** 交底书表头 + `evidence.json` 的 `metadata`(公开状态、`prior_filings`、`[待确认:…]` 项)。
**门禁** 🚦 起草前与发明人确认表头;公开状态已如实记录;在先申请已检索并留痕(找到或写明未找到)。

### 阶段 1 —— 源材料映射与核实

**先清点,再取用。**

```bash
find . -maxdepth 3 -type d -not -path '*/.*' | sort
```

逐个目录表态(读了 / 与本发明无关 / 打不开)写进 `evidence.json` 的 `metadata.inventory`,三个字的理由就够。**清单只能确认你想到的东西,发现不了你没想到的**——清单外的目录连同里面的证据一起静默消失,而稿子看上去是完整的。

**通读主文档全文,并逐节表态。** 把它的章节目录列出来,每一节要么在 `source_map` 里至少有一条 ID,要么在 `metadata.source_coverage` 里写明"与本发明无关"。Methods 讲机理,而最终进入从属权利要求的数值区间,同样经常写在 Results、图注或补充表里;只读 Methods 是后续产生假 `needs-confirmation` 的具体成因(见阶段 2)。

**逐节表态不是形式主义:材料一多,这一步就会被挤薄,而且挤薄了没有任何迹象。** 已经量过一次——同一篇论文,只给论文时它内部的自相矛盾被发现了,再加上几十兆源码之后**同一处矛盾就漏掉了**,两次都漏。注意力被代码吃掉是默认结果,不是意外,所以这里需要一个不受材料量影响的独立门禁。

#### 核实:一个事实有几个载体,就对几次

核实范围由一条规则决定:**凡是将出现在权利要求、公式或效果表中的数值与关系,都要核。** 其余的可以不核。按这条规则展开:算法类落到网络规模、定义式、数据集规模与类别分布、阈值常量;机械类落到尺寸、配合关系、材料牌号;化学类落到配比、温度与时间、表征数据。领域不同,规则不变。

核实的做法也只有一条:**给每个这样的事实清点载体——它在材料里出现过哪些地方——两个以上的逐一对。**

**载体不分种类,同等对待:** 同一份文档的不同位置(正文、表、图注、摘要、附录)、不同文档(论文、技术报告、学位论文章节、README、实验记录、汇报材料)、配置文件与代码常量、检查点里的超参、运行产物与结果文件。

**只有一个载体的**,在台账里标明——这不是"核实过了",是"无从核实"。载体数量本身就是给代理师的信息:哪些数字经得起推敲、哪些只是孤证。

规则不因材料构成而变,变的只是载体从哪来:

| 手头有什么 | 载体主要来自 |
|---|---|
| 论文 + 代码 | 论文各节之间、论文与配置/常量、结果文件 |
| 只有论文 | 论文自己的不同位置——正文与表、表与图注、摘要与正文,以及算术自不自洽 |
| 只有项目与代码(论文还没写) | 两份配置之间、README 与配置、常量定义处与使用处、实验记录与产物 |

**没有"材料不够就跳过核实"这回事。少的是载体,不是规则。**

只有代码没有论文时,数值反而更硬——直接读代码是第 2 级证据,高于论文。那种情形缺的不是数字,是**技术效果与对比数据**:为什么这么做、比现有做法好在哪、好多少。代码里一个字都没有,**必须向发明人要,要不到就留白,绝不从代码推想出效果**。

#### 对不上的三类,以及怎么处置

| 类型 | 长什么样 | 判据 |
|---|---|---|
| ① 同一个量,两处不同值 | 正文写 85.29%,表 3 写 88.23%,指的是同一格 | 两个载体摆一起比 |
| ② 同一个参数,两节不同值 | §2.2 写 K=30,§3.1 写 K=48 | 同上 |
| ③ 一处记载自己就不成立 | 序列 81 bp 去掉 6 bp 与 2 bp 剩 73,却说"等分为 10 段"。73 ÷ 10 除不尽 | **把文中数字代进它自己描述的运算**,看做不做得出来 |

**①②的处置:** 按证据强度序位取高者作为**临时占位**,让起草能往下走;把两个值连同各自出处记进 `metadata.discrepancies`,并**为每一条立一个待确认项**,写明「A 处记 X、B 处记 Y,实际以哪个为准」。

序位只能告诉你暂时用哪个,**告诉不了你哪个是对的**——论文 30 而代码 48,可能是代码有 bug 而发明人本意是 30;而正文 85.29 与表 88.23 同属论文、`max_iters` 的 50 与 500000 同属代码,**同级证据内部打架时序位直接失效**。第 33 条之下猜错补不回来,所以这类一律问发明人。这正好是「怎么问发明人」允许的那类——**技术事实,他比你懂**。

**③的处置:** 问法不同。不是"以哪个为准",而是「按这个数算不出来,实际是怎么做的」。在把它问清楚之前,**不要臆造一个能算得通的规则写进说明书**。

#### 自由深读(有源码时必做)

上面那步是**定向核实**:拿着一份待核清单去比对。做完之后,**再无目的地把源码通读一遍**,不带清单,不带问题,就看代码实际在做什么。发现的反常写进 `metadata.anomalies`,每条给出 `file:line`。

为什么要单列一步:**定向核实只能确认你已经在问的问题,答不了你还没想到要问的。** 而实现层面的缺陷恰恰长在没人想到要问的地方——一个掩码把有效词元当成了填充位、一次张量重排让"多头"根本不是多头、一处归一化被注释掉之后再没打开。这些在论文里一个字都没有,在待核清单上也不会出现,只有把代码当代码读才会撞见。

已经量过一次:同一份源码,**不带流程自由读的那一组,比按八阶段走完的那一组多挖出一层实现缺陷**。差别不在能力,在于时间花到哪儿去了——填表的时间没有用来读代码。所以这一步要**显式留出来**,不能指望它在别的步骤里顺带发生。

发现之后的处置分两种,不要混:

- **与权利要求承重的数值或关系有关** —— 按上面「对不上的三类」处理:临时占位 + 两个值都记 + 立待确认项
- **是实现缺陷本身** —— 不要塞进权利要求。它可能是发明的一部分(那就作为实施细节如实写进说明书,并列为待确认),也可能纯粹是 bug(那就只报告发明人)。**判断不了就两条都做:说明书如实描述实际行为,同时进 `QUESTIONS`**

**产物** `evidence.json` 的 `metadata.inventory`、`metadata.source_coverage`、`metadata.discrepancies`、`metadata.anomalies`(有源码时)与 `source_map`(每条带 `file:line` 或章节定位)。
**门禁** 每个目录都已表态;主文档每一节都已表态;有源码时自由深读已做;凡将进入权项、公式或效果表的数值,都已清点载体并逐一对过,或已注明是孤证;每一处对不上都有对应的待确认项。

### 阶段 2 —— 证据台账

对每条候选技术特征,记录:特征表述、`source_ids`、技术作用、效果,以及下列四选一的支持状态:

| 状态 | 含义 | 可否写入权利要求 |
|---|---|---|
| `explicit` | 论文中有记载,或代码中有实现 | 可以 |
| `inherent` | 围绕已记载值的常规实施裕度 | 可以 |
| `needs-confirmation` | 貌似合理但任何可得来源中均无记载 | **不可** —— 降入说明书,或问发明人 |
| `unsupported` | 无依据,或与代码矛盾 | **不可** —— 完全排除 |

写 `evidence.json`。

权利要求里的**数值范围**,需要"该范围本身"有记载依据,而不是范围内某个取值有依据。「论文写 0.15,所以权项写 0.10–0.20」是 `inherent`;「论文没给范围,我挑了个看着合理的」是 `needs-confirmation`。

#### 降级之前必须穷尽检索

校验器核对"台账 ↔ 权利要求",核对不了"台账 ↔ 事实"——标成 `needs-confirmation` 它就照单全收,门禁随即删掉一条本来站得住的权利要求。

**默认的失败不是"确实没依据",而是"没查全"。**

给任何特征标 `needs-confirmation` 之前,**凡是手头有的来源都要查过**:

1. **论文全文,不是某一节**(理由见阶段 1)。对目标量做全文检索,不要只翻你预期它在的那一节。
2. **配置文件。** 论文里没有的超参,通常在 `configs/*.yaml` 或训练脚本的 argparse 默认值里。
3. **运行产物。** `runs/`、检查点、输出文件名记录了实际扫过哪些取值。
4. **消费该值的代码。** 常量的定义处给出它的名字,使用处给出它的边界。

后三项在没有代码库时自然不适用;这时**第一项要查得更彻底**,并且可以直接问发明人——他口述的取值是第 4 级证据,写进说明书没问题,只是不宜写进权利要求的数值限定。

可得来源都查空之后才轮到 `needs-confirmation`,并把**查过哪些、哪些不可得**写进该条目的 `note`——校验器会检查这条(`UNDOCUMENTED_DOWNGRADE`)。

**已经出过一次错:** 某个超参数的取值区间被判无据、整条从属权利要求被删,而它在 Results 正文与图注里逐字写着,只因当时只读了 Methods。删掉有支撑的权利要求是静默且永久的 (第 33 条不让补回),所以"宁可保守"在这里不是安全默认。

**产物** `evidence.json` 的 `evidence_ledger`。
**门禁** `python scripts/check_evidence.py 交底书.md evidence.json` 无 ERROR。

### 阶段 3 —— 划分必要特征与优选特征,然后写权利要求

把特征分成**必要特征链**(→ 独立权利要求)与**优选细化**(→ 从属权利要求)。这个划分是交底书承载的最有价值的东西,代理师做不了。

独立权利要求写成闭环:技术输入 → 相互配合的操作 → **具体的领域产物**。末端落在「设计结果」这类空话上,等于没有限定任何东西。

遵循 `TEMPLATE` 里的形式惯例:步骤编号 `1）2）2.1）`、`其特征在于` 过渡语、尾部两条存储介质与电子设备权项。

**产物** 交底书的「权利要求书」一节 + `evidence.json` 的 `claim_feature_map`。
**门禁** `python scripts/check_claims.py 交底书.md` 无 ERROR。

### 阶段 4 —— 说明书

五节的标题与顺序法定,见 `TEMPLATE` 第三节。这里只说每节写什么:

- **背景技术** —— 列举已知路线,每条给出**机理层面的技术缺陷**。「性能更差」不是技术缺陷;要落到"这个做法在原理上会导致什么"这一层。不得把本发明自身作为背景技术。要引用**专利文献**,不能只有学术文献——见下。
- **发明内容** —— 发明目的 / 构思 / 优点。每条优点都要绑定到具体的技术手段。
- **具体实施方式** —— 每个实施例对应一种**实质不同的实施方式**,不是发明内容的复述。

#### 检索到什么程度

**本技能不做查新。** 不评估新颖性、不给可专利性结论——那是代理师的活,也需要专业数据库。此处只做一件事:**为背景技术找几篇同技术方向的专利文献**,因为代理师论证创造性的地基就在这一节,而已有材料里通常只有学术文献。

这一步找的是**别人的**专利。**自己人的在先申请在阶段 0 就该查完**,两者目的与检索式都不同,不要混为一谈。

三条硬规矩:

1. **每一篇都要打开看过。** 检索结果的标题与摘要经常和正文对不上。专利号、申请人、公开日,以及你说它有什么缺陷——四样都要与原文对得上才能写。
2. **搜不到就留白,不许填。** 写 `[待检索:<技术方向>]` 并记进 `QUESTIONS`,交给代理师补。留白是可见的缺口,编造的专利号是隐性的地雷——审查员一核就穿,而且会连累整篇的可信度。
3. **无法联网时,整节按第 2 条处理**,并把 `metadata.assurance.patent_search` 记成 `{"done": false, "reason": "…"}`——校验器查这一条(`ASSURANCE_NO_REASON`)。不要用学术文献冒充,也不要凭印象写号码。

#### 效果对比表

效果数据是支撑创造性的主要材料,交底书可自由使用表格,应当放。行为对照方法(含本发明与各现有技术路线),列为评价指标,并注明测试条件(样本量、数据集、评价口径)。

按证据强度序位取数:

- **有结果文件时**,从结果文件取,不要从论文誊抄——论文里的数字可能过时、可能来自另一次运行、可能经过四舍五入或口径调整。把产出该数字的文件记进 `source_map`。
- **只有论文时**,从论文取,记论文行号。这完全正当,不必因无从核对而放弃整张表。
- **两者都有且对不上时**,以结果文件为准,两个值都记下并报告给发明人。

无论取自哪一级,表下都用一句话写明来源与测试条件。**唯一不可以的是把来源写得比实际强**——没核对过就别说核对过。表里有一个来路不明的数,整张表在审查员眼里就都不可信了。

**按数据写,不照抄论文的概括表述。** 论文常有"在全部指标上均显著优于"这类总结,而它自己的表里往往有一两列并非最优。不必去评判论文写得对不对——**只要交底书不这么写就行**:照表列出各项数值、注明测试条件,哪项领先哪项持平让数据自己说,再针对领先的项说明是哪个技术手段带来的。

这不是吹毛求疵。效果表是支撑创造性的主要材料,而**审查员会逐格核对**;一句站不住的概括被核穿,连累的是整张表的可信度,而不只是那一句。

#### 深度标定

标准不是字数,是:**同行照着这份文档,不再做研发能不能实现?** 达不到即第 26.3 条公开不充分,而该缺陷在答复阶段无法补救。**别拿别处交底书的篇幅当标准**——那只说明当地惯例,不说明够不够;按上述标准,算法类发明通常要写到常见篇幅的数倍。

这个标准不可机械判定,但可以逐项自查。**主实施例必须回答完下面每一个问题**,答不上来的就是缺口——同行照着做,恰恰会卡在你答不上来的那一步:

1. **输入从哪来、怎么变成模型能吃的形态?** 数据源、筛选条件、预处理、划分方式。
2. **系统由哪些部分构成、各部分收什么发什么?** 结构、规模、连接关系。
3. **怎么把它调到能用?** 训练或标定的目标函数、优化方式、关键超参、终止条件。
4. **怎么用它产出结果?** 推理或运行的参数、迭代方式、终止条件。
5. **产出之后还要做什么才能交付?** 后处理、筛选阈值、失败样本的处置。
6. **每个数值从哪来?** 见阶段 1 的核实要求。

第 3 项是最容易被写空的一项。「采用 AdamW 优化器,余弦衰减,早停」不算回答——同行据此复现不出来;要写到学习率、批大小、预热、梯度裁剪、最多轮数这一层。凡是你跑实验时需要写进配置文件的东西,同行也需要。

上述六问按算法类发明展开;换领域时问题不变,展开的内容随之改变(机械类第 2 问答的是零件与配合,第 3 问答的是加工与装配参数)。

工作目录下若有此前定稿的交底书,读它——用语习惯与颗粒度照搬,能省掉与代理师的来回。

#### 🚦 实质评审(第一轮,就在这里做)

权利要求与说明书刚成型、还没往下写,**这是唯一一个改动代价还低的位置**。再往后走,可替代实施方式、附图标记、效果表都会绑到现有的权项措辞上,那时改一条独权要牵动四处。

四个校验器只查形式与溯源,查不了实质。实质问题——权项是否清楚、是否得到说明书支持、公开是否充分、创造性论证是否闭环、有没有把没依据的东西写进权项——要另一个模型以审查员视角读一遍。

用 `mcp__codex__codex` 调 `REVIEWER_MODEL`,推理强度 `high`。**提示词模板与已知失误模式见 `references/examiner-review.md`**。核心一条:把它的每一条都当作**待核实的断言**,不是结论——它两个方向都会出错,既会把对的说成错的,也会漏掉最严重的。逐条自己去查实,查实了才改。

它提的每一条,处置结果都要落到纸面:采纳的直接改,不采纳的写进 `QUESTIONS` 或对应台账条目的 `note`,写明为什么不采纳。**不留痕的"看过了"等于没看。**

**产物** 交底书「说明书」五节。
**门禁** 🚦 首轮实质评审已做,每条意见都有处置记录(改了,或写明为何不改);`metadata.assurance.external_review` 已如实填写——**做了就记模型,没做就记原因**。

### 阶段 5 —— 可替代实施方式

写这一节之前先读 `references/alternatives-discipline.md`。这是全篇最容易编造的部分,而在此处编造会触发第 26.3 条公开不充分——**后果比保护范围写窄严重得多**。

**顺序是:先抽取,再逐项处置,最后才动笔。**

```bash
python scripts/check_alternatives.py 交底书.md --extract    # 1. 先出待办清单
#    → 逐项填 alternatives.json，每项非 essential 即 alternative + status + basis
python scripts/check_alternatives.py 交底书.md alternatives.json   # 2. 校验
```

不要反过来——凭印象写完一节再跑校验补漏,漏的一定是你没想起来的那些,而"没想起来" 恰恰是抽取要解决的问题。**权利要求里的每一个数值都必须有处置**:要么标 essential (该选择不可替换),要么给出替代方案与依据。校验器对权项数值单独把关 (`UNDISPOSED_CLAIM_VALUES`);实施例里的数值多为事实而非选择,由补充说明兜底即可。

同样适用降级纪律:标 `speculative` 之前,按阶段 2 那四处穷尽检索。

**产物** `alternatives.json` + 交底书「可替代实施方式」一节。
**门禁** `python scripts/check_alternatives.py 交底书.md alternatives.json` 无 ERROR。

### 阶段 6 —— 附图

覆盖度由一条规则定:**权利要求 1 里每一组成组的步骤,都应当有一张图能对上**。指不到图的步骤,说明缺图。

画图前读 `references/figure-standards.md`:两类图的做法差别、该画哪几张、结构图的五条验收标准、附图标记的颗粒度。

```bash
python scripts/render_figures.py --check-env                        # 先确认环境
python scripts/render_figures.py --specs figures/specs --out figures
```

渲染器随技能分发,中文字体由脚本自动挑选并绑定;挑不出可用字体就报错停下,不会先渲一堆废图。原理与环境处置见 `figure-standards.md`。

**spec 里的下标与上标必须写成 `x_{1}` / `x^{i}` 的花括号形式**,写 `t_next` 会原样渲染成字面下划线——这个错已经犯过两次,`check_figures.py` 会拦(`RAW_SUBSCRIPT`)。

**渲染完必须逐张看过。** 自动布局的连线会穿过方框、长标签会压住相邻节点,这些校验器查不出来,只能看。看这五样:

1. **汉字有没有变成空心方框。** 脚本会拦住绝大多数情形,但它自检不了时会在 stderr 出声并放行——那一行不能当没看见
2. 标签有没有压在方框或连线上
3. 连线有没有穿过中间的方框——反馈线的通道要走在列与列之间的空隙里
4. 文字有没有超出画布边界被截断
5. 缩到三分之二大小时还认不认得清

一次成的概率很低,调坐标重渲两三轮是常态。别渲完就交。

**产物** `figures/specs/*.json` + `figures/fig*.png`。
**门禁** `python scripts/check_figures.py 交底书.md` 无 ERROR;五项目视自查已逐张过。

## 问发明人

发明人通常不懂专利法,**只问两类**:

**一、技术事实**——他比你懂。「这个参数换成 X 能跑通吗」「实测值与论文记载不符,是论文漏算了吗」。

**二、法律签字**——只有他能做:表头那句公开充分性核准声明。

**不要问的:** 哪条特征该进独权、某个状态该不该降级、要不要删某条权利要求、数值范围写多宽。这些是本技能的职责,推给发明人只会换来「我不懂」,正确做法是自己去把事实查实。

下面这些任何材料里都没有,**必须显式问**:

1. 哪些特征是必要的,哪些是优选的
2. 现有技术在机理上的缺陷
3. 每个设计选择的替代方案,以及**你凭什么知道它能行**
4. 公开状态——时间、地点、形式
5. **本领域有没有法定的附加提交物。** 凡有,现在就提,代理师需要提前量。判断不了就把已披露的内容形态告诉代理师,由他定——生物序列的序列表、新微生物菌种的保藏证明、遗传资源的来源披露登记表,都属此类
