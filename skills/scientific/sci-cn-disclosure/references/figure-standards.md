# 附图:该画哪几张、画到什么程度

阶段 6 读本文件。编号与渲染约定的检查由 `scripts/check_figures.py` 执行。

## 该画哪几张

**权利要求 1 里每一组成组的步骤,都应当有一张图能对上。** 通常是这几张,按需增减:

| 图 | 类型 | 对应 |
|---|---|---|
| 总体框架 | 结构示意 | 权 1 的全部步骤,一图概览 |
| 核心部件的内部结构 | 结构示意 | 权 1 中"构建 / 设置"类步骤 |
| 制备或训练流程 | 流程图 | 权 1 中准备阶段的各步骤 |
| 运行或生成流程 | 流程图 | 权 1 中执行阶段的各步骤 |
| 后处理或检验流程 | 流程图 | 权 1 中筛选、输出相关的步骤 |

对照检查:把权 1 的步骤逐条列出来,每条都要能指到某一张图的某个节点。指不到的说明缺图。

## 两类图,做法不同,不要混用

**流程图**可由权利要求的步骤序列生成。节点与权项步骤一一对应,末端节点写具体产物。

**结构示意图**(总体框架、部件组成、装配关系、数据或物料通路)**不能自动生成**——自动布局只会产出一堆等大方框加直箭头,那是流程图不是结构图。手工写 spec。

## 结构示意图的验收标准

下列五条适用于**全部结构示意图,总体框架图也在内**。总体框架图最容易被误当成流程图画成一串方框,那样就丢掉了"被处理的东西长什么样"这一层信息(达不到就是没画):

1. **画出被处理的对象本身**,不只是处理它的部件。让读者看得出这个部件到底对什么做了什么——序列类画词元条带并标出特殊位点,图像类画尺寸变化,信号类画波形或频谱,机械类画工件在各工位的形态,化工类画物料在各单元的相态。
2. **核心部件要展开内部。** 整篇发明的关键在哪一层,哪一层就画到子结构级别:子部件的顺序、旁路走向、接口位置、外部条件从哪里接入。其余部件折叠成一个框。
3. **汇合与作用要有符号。** 相加、相乘、拼接、门控、混合、换热,用 ⊕ ⊙ ⊗ 这类符号标出来,不要只画一条箭头汇入。
4. **旁路与回路必须可见。** 跳接、回流、反馈、条件通路往往正是区别于现有技术的地方,被画成直线串联就把发明点抹掉了。
5. **输入与输出各标一次规格。** 维度、长度、通道数、尺寸、流量、浓度——让读者能自己推出中间状态。

一份合格的结构图,节点数通常在数十个量级;若只有六七个框,说明还停在流程图层面。

## 渲染

两类图都用 `scripts/render_figures.py`,它在基础渲染器之上补了中文字体绑定、下标排版、正交反馈回路、分组标签加深四件事:

```bash
python scripts/render_figures.py --check-env                        # 先自检环境
python scripts/render_figures.py --specs figures/specs --out figures
```

基础渲染器(`scripts/vendor/figure_renderer.py`)随技能一起分发,不依赖外部检出。

**中文字体不是可选项。** cairosvg 走 cairo 的 toy font API,**不做逐字形回退**——font-family 里第一个匹配上的族拿不出汉字,它就画 .notdef 空心方框,不会去试下一个族。所以脚本会自己挑一个装了的、且经位图自检确有汉字字形的族名,插到 font-family 最前面。挑不出来就报错停下,不会渲出一堆豆腐块让你事后才发现。

| 情况 | 脚本行为 |
|---|---|
| 系统无中文字体 | 报错退出,并给出 apt / dnf / conda 的安装命令 |
| 装了但 fontconfig 没收录 | 报错,提示用 `CN_DISCLOSURE_CJK_FONT=<族名>` 直接指定 |
| 想换字体 | `--font "<族名>"` 或同名环境变量 |
| 基础渲染器换位置 | `CN_DISCLOSURE_RENDERER=<路径>` |

**spec 里的下标与上标必须写成 `x_{1}` / `x^{i}` 的花括号形式。** 写 `t_next`、`h_c` 这种不带花括号的,会原样渲染成带下划线的字面文本,看上去像没排版的源码——这个错已经犯过两次。`check_figures.py` 会检查这一条(`RAW_SUBSCRIPT`)。

## 附图标记的颗粒度

标记连续编号,同一部件在各图中编号一致。**附图中出现的每个标记,都必须在说明书文字部分被提及。**

编到多细,由一条规则决定:**凡是说明书正文需要单独指认的部件,都要有编号。** 判断办法:写实施例时,凡是你写出「……经 X 后送入 Y……」这种句子的地方,X 与 Y 就都该有编号。只给顶层对象编号而不给内部部件编号,正文就只能含糊地说「送入该装置」,失去与附图的精确绑定——而附图标记正是审查员逐个核对的东西。

**「名称紧接编号」不只是行文建议,是校验器真正在查的东西。** `check_figures.py` 判定一个标记有没有被提及,看的是**编号紧邻的前文里有没有该部件名称的痕迹**(允许缩写:声明「三通换热器」、正文写「换热器 13」也算)。名称在别处出现过、却从没紧接着编号写,记 `NUMERAL_NOT_ANCHORED`——散落的名称起不到绑定作用。

这条判据**不认识任何计量单位**,所以「间隙 5 mm」「温度 7 ℃」「压力 3 MPa」都不会被误当成对标记 5 / 7 / 3 的提及,换什么领域都一样。早先的做法是反过来的:列一张数量单位黑名单把数值排除掉——那张表只列了一个领域的单位,别的领域一进来整条检查就失灵,该报的错一条不报。**别改回去。**

达到这个颗粒度时,实施例读起来应当是这样的:

> 物料经进料泵 11 送入预热器 12，再由三通阀 13 分配至反应釜 18……

而不是「物料经泵送入预热器,再分配至反应釜……」。

画完后把图片以 `![图N](路径)` 插入交底书文末的「附图」一节,否则附图说明写得再全,交出去仍是一份没有图的稿子。
