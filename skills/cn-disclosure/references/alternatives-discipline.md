# 可替代实施方式:纪律

权利要求的保护范围受《专利法》第 26.4 条约束——权利要求必须得到说明书支持。说明书里只写了余弦调度,权利要求就只能写余弦调度;写了"余弦、线性、多项式均可,只要满足端点与单调条件",才敢往上位写成"任意满足该条件的调度函数"。而第 33 条规定申请日之后不得增加超出原说明书范围的内容:**申请日没写进去的替代方案,以后永远补不进来。** 这是整份交底书里唯一一个"现在不写就彻底没了"的部分。

它同时也最容易写错。生成替代方案的默认行为是**联想**——"除了余弦还有什么?线性、多项式、指数……"。联想出来的都合理,但其中真能跑的和纯属编造的混在一起,事后分不出来。而这里编错的代价高于范围窄:说明书写了"也可以用 X",若本领域技术人员照做实现不了,构成第 26.3 条公开不充分,**整份申请可能被驳**,不只是那一条替代失效。

所以本节的机制不是"生成替代方案",是"**为每个替代方案举证**"。

## 四态

每条替代方案必须落到下列四态之一。前三态可写入正文,第四态禁止。

### `tested` — 实际跑过

已有材料里存在该替代方案被实际实施过的证据。

- 判据:给得出具体出处——运行目录、配置文件、试验记录或检测报告的路径,或论文中报告了该设置下的实验结果。**没有代码库时,论文里的消融实验、对照实验、参数扫描同样构成 `tested`。**
- 例:"反应温度亦可取 160 ℃"——该温度下的对照批次见 `runs/exp_160c/`,收率记录在试制报告第 4 节。

### `derivable` — 可从已披露的关系推出

不需要实验,因为从已披露的数学关系、代码结构、物理约束或结构配合可推出该替代必然成立。**必须写出推理链。** 只有论文时,公式与其成立条件就是推理的依据,不必有代码。

- 例(算法):"调度函数可取任意满足 γ(0)=0、γ(1)=1 且单调递增的函数"——这三个条件恰是 `src/model.py:316` 中 `p = 1 − γ(t₂)/γ(t₁)` 取正值的充要约束,函数的具体形状只影响该过程在时间轴上的疏密。
- 例(机械):"密封圈材料可换为任意在工作温区内保持弹性的弹性体"——该件在方案中只承担轴向密封,材料要求由工作温区与介质相容性两个条件完全确定,牌号本身不参与配合。

### `routine` — 本领域常规替换

同行看了说明书无需再做研发即可实施。**必须说得出为什么常规。**

- 典型形态:把一个数值换成同类数值;把一个现成模块换成另一个现成模块;把一种测量口径换成另一种同量纲口径。
- 例:"三分量混合模型可取 2 个或 4 个以上分量"——改一个参数。
- 例:"进料计量可由质量流量计改为体积流量计配密度换算"——两者给出的是同一物理量,方法对该输入的要求仅此而已。

注意:"这个阈值可以调"是 `routine`(改常量);"这个阈值可取 25% 至 60%"是**另一回事**——除非跑过或推得出,那个区间就是编的。**写"参数可调"而不写区间。**

### `speculative` — 禁止写入

看着合理,但既没跑过,也推不出,也不属常规替换。

- 例:"所述网络亦可采用空洞卷积或状态空间模型"——没试过,也推不出。
- 例:"混合模型可换成对数正态或伽马分布族"——同上。
- 处置:删除;或补实验升级为 `tested`;或改写成推得出的更弱表述。

**标 `speculative` 之前先穷尽检索。** 与 `needs-confirmation` 同理:默认的失败不是"确实没依据",而是"没查全"。全文(含 Results 与图注)、配置文件、运行产物、消费该值的代码——**凡是手头有的都要查过**再降级,并把查过哪些、哪些不可得写进 `basis`。误判 `speculative` 的代价是白丢一块保护范围,而第 33 条不允许事后补回。

## 完整性:替代项要枚举,不能靠想

有了四态还不够——怎么知道没漏掉该写的?

**从文档里机械抽取所有"具体选择",逐项处置。** 具体选择包括:

- 权利要求与实施例中的每个数字字面量(尺寸、配比、温度、时长、层数、维度、阈值、计数)
- 每个具名技术选择(结构形式、材料牌号、工艺路线、函数形式、统计模型、模块架构、评价口径)

每一项要么给出替代方案(带状态与依据),要么显式标 `essential`——即该选择不可替换,是必要技术特征。**没有处置的项,校验器报错。**

这一步顺带完成另一件事:**必要特征与优选特征的划分**。标 `essential` 的进独立权利要求;有替代的进从属权利要求或说明书。两件事本是一体两面。

## 台账格式

`alternatives.json`:

```json
{
  "choices": [
    {
      "id": "A01",
      "choice": "余弦调度 γ(t)=1−cos(πt/2)",
      "locus": "权1 步骤2.3；实施例一 步骤二",
      "disposition": "alternative",
      "alternatives": ["线性调度 γ(t)=t", "多项式调度 γ(t)=t^k (k>0)"],
      "status": "derivable",
      "basis": "端点条件与单调性是 src/model.py:316 中该概率取正的充要约束；形状仅影响疏密"
    },
    {
      "id": "A02",
      "choice": "在原生离散符号空间上直接建模",
      "locus": "权1 步骤1）",
      "disposition": "essential",
      "reason": "不经连续松弛是本发明区别于现有路线的核心，替换即改变发明实质"
    }
  ]
}
```

字段:

- `disposition` — `alternative` 或 `essential`,二选一。
- `status` — 仅 `alternative` 时必填,取 `tested` / `derivable` / `routine` / `speculative`。
- `basis` — 仅 `alternative` 时必填。`tested` 给路径,`derivable` 给推理链,`routine` 给"为什么常规"。空泛的一句"本领域常规手段"不算依据。
- `reason` — 仅 `essential` 时必填。

## 怎么写进正文

```
实施例采用 X。作为可替代的实施方式，所述 X 还可以采用 Y 或 Z，
只要满足 <该选择在方法中实际承担的约束> 即可。
```

把**约束**写出来比把替代项列全更重要——约束是上位概括的依据,替代项只是例示。

笼统兜底("上述具体数值均为示例性的,本领域技术人员可根据需要调整")支撑力很弱,审查员通常不认它能支撑上位概括。可以保留,但只用来兜那些**没有逐项列举**的次要参数;真正影响保护范围的选择必须逐项具体写。
