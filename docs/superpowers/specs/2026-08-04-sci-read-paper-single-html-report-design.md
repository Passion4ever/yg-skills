# `sci-read-paper` 单文件 HTML 精读报告设计

## 1. 目的

`sci-read-paper` 的默认产物应当像一位领域专家带读论文：先说明研究为什么出现，再重建作者怎样从问题走到方法，随后追踪数据、训练、模型和实验，最后集中审查证据并形成自己的结论。

本次设计同时解决三个问题：

1. 固定八个正文部分的标题、职责和叙事顺序，避免背景、方法、实验与批判相互混写。
2. 删除独立的“阅读导航”正文部分，把其有用信息改造成页面顶部信息卡和可点击目录。
3. 将 standard 与 audit 模式的最终交付统一为一个自包含 HTML 文件，在不牺牲证据追踪的前提下替代多份 Markdown。

## 2. 核心阅读顺序

```text
为什么研究这个问题
→ 整篇论文的全局地图
→ 问题如何导向方法
→ 数据怎样形成并进入训练
→ 数据怎样在模型中变成输出
→ 实验怎样回答研究问题
→ 证据实际支持到哪里
→ 读者最终应该带走什么
```

Sections 1–6 以理解作者为主，Section 7 明确切换到审稿人视角，Section 8 综合方法价值与证据边界。会改变结论的事实在前六节仍需以中性“证据边界”出现，但替代解释、影响评级和裁决集中在第 7 节。

## 3. 固定正文结构

### 3.1 Section 1 — 为什么要做这项研究：背景、现状与本文切入点

回答“为什么会有这篇论文”。采用四段式逻辑：

1. **任务背景与意义**：先写模型的字面输入与预测目标，再解释科学或工程意义。预测目标必须与样本构造/标注代理、生物机制分开。
2. **现有研究进展**：解释主流方法已经解决了什么，不按论文清单罗列文献。
3. **仍然存在的关键不足**：说明哪个限制真正阻碍任务，以及为什么重要。
4. **本文如何切入**：用高层语言说明作者的假设和总体方案，不展开模块、超参数或实验裁决。

### 3.2 Section 2 — 三分钟建立论文全局地图

回答“整篇论文怎样从问题走到结果”。它不是摘要，也不重复 Section 1。依次给出：

1. 预测任务与中心矛盾；
2. 作者的总体解决思路；
3. 最小数据流；
4. 支撑中心故事的两到三个报告结果；
5. 一句指向 Section 7 的审查预告。

这一节必须能够独立阅读，但不能替代后续深读。

### 3.3 Section 3 — 从问题到方法：作者为什么这样设计

回答“每项关键设计是被什么问题推出来的”。开头声明：这是根据论文论证、方法结构与代码证据重建的设计逻辑，不等于作者真实的心理过程或研究时间顺序。

主要设计按以下因果模板展开：

```text
遇到了什么问题
→ 作者提出什么假设
→ 因此采用什么设计
→ 该设计预期改变什么
→ 为什么还需要下一项设计
```

本节不详细重复数据数量、张量形状、超参数和实验可信度。

### 3.4 Section 4 — 数据从哪里来，又怎样进入训练

回答“一个样本如何从原始来源走到模型入口”。先跟踪一个具体样本，再扩展到整个数据集：

1. 原始来源、版本和采集条件；
2. 样本筛选、标签构造、去重和预处理；
3. 数据集组成、类别比例、增强和各子集作用；
4. train/validation/test 的划分单位及潜在亲缘或派生关系；
5. batch、配对、conditioning、训练阶段、loss、关键超参数和 checkpoint 选择；
6. 论文与代码在上述步骤中的缺失或冲突。

本节到“模型入口和训练信号”为止；模型内部变换属于 Section 5，泄漏或泛化后果的裁决属于 Section 7。

### 3.5 Section 5 — 模型内部：数据怎样一步步变成输出

回答“同一条样本进入模型后发生了什么”。先给一张简化主路径图，再按执行顺序解释。每个核心阶段回答：

```text
现在的数据是什么？
形状或结构是什么？
模块执行了什么操作？
获得或丢失了什么信息？
为什么需要这一步？
输出流向哪里？
论文和代码是否一致？
```

直观解释先于公式；公式中的符号立即对应真实对象。主报告保留必要张量、图结构、条件变量和解码过程，不抄写全部接口与配置。计算输出与生物、化学或临床事实必须保持层级区分。

### 3.6 Section 6 — 实验逻辑：每项实验在回答什么问题

回答“整套实验怎样围绕论文主张组织”。先给出实验地图，将内容区分为 main/baseline comparison、control、ablation、robustness/generalization、analysis、case study 和 external validation。

随后按研究问题而不是表格编号组织，每项核心实验采用：

```text
作者要回答什么？
这是什么类型的实验？
实验怎样设计？
改变了什么，控制了什么？
使用什么数据和指标？
实际观察到什么？
作者据此主张什么？
证据边界在哪里？
```

必须区分“观察结果”和“作者解释”。本节不回答最终是否支持该解释；累计判断属于 Section 7。

### 3.7 Section 7 — 批判性审查：证据究竟支持到哪里

开头明确切换到审稿人视角。先拆分论文的主张层级：数据/方法、计算性能、泛化、机制或领域事实、新颖性。不同主张不能共享同一证据门槛。

问题按以下优先级排列：

1. 会直接改变中心结论的问题；
2. 泛化、真实应用或领域有效性限制；
3. 可复现性和论文—代码一致性；
4. 次要解释或表达问题。

每个关键议题使用审查卡：

```text
审查议题：
作者主张：
支持证据：
反证或替代解释：
证据缺少什么：
对中心结论的影响：
最小解决实验：
```

“对中心结论的影响”必须校准为：不影响、降低置信度、缩小适用范围、只能支持更弱结论，或直接否定某项主张。结尾统一给出“可以相信、可以暂时相信、当前不能推出、被现有证据否定”。

### 3.8 Section 8 — 读完这篇论文，真正应该带走什么

不重复摘要或 Section 7 的问题列表，而是完成综合：

1. **论文真正贡献了什么**：区分新能力、新方法、新数据构造、新组合、工程改进或评估变化。
2. **最终可以相信到哪里**：用最短形式给出校准后的最终结论。
3. **如果继续这项研究，下一步最该做什么**：提出一到三个最有决定性的实验或改进。

## 4. 顶部信息区与导航

删除 `阅读导航` 这一正文标题，但保留其必要功能。HTML 顶部由以下内容组成：

- 论文标题、作者、期刊/会议、年份、DOI 或稳定标识符；
- `mode: standard|audit` 与 `status: complete|partial`；
- 三张信息卡：`作者主线`、`证据状态`、`审查入口`；
- 可折叠的“报告与版本信息”：论文版本、代码 commit、访问日期、关键缺失材料；
- “快速阅读”链接，直接进入 Section 2；
- 固定或粘性目录，链接到八个正文部分。

不再显示“生成文件列表”。状态为 `partial` 时，顶部信息卡只说明受影响的结论和最小补全材料；具体缺口在相关正文处通过证据边界再次出现。

## 5. 单文件 HTML 输出

### 5.1 文件合同

Standard 模式默认只交付：

```text
<paper-slug>.html
```

Audit 模式也只交付一个 HTML，文件名为 `<paper-slug>-audit.html`；在相同八节正文之后增加四个可折叠 audit panels：data/training audit、model dataflow audit、experiment matrix 和 extended critical review。用户每次只获得所选模式对应的一个文件；不同模式不会相互覆盖。

检索、核查和写作过程中可以使用临时工作材料，但不得把它们作为最终输出目录中的额外交付文件。HTML 本身是最终可追踪档案。

### 5.2 页面语义结构

使用可读、可解析的语义 HTML：

```text
html
├── header: metadata + three summary cards + details#report-info
├── nav: eight-section table of contents
├── main
│   ├── section#section-1 ... section#section-8
│   ├── details#figure-briefs
│   └── audit-only details panels
└── footer
    └── details#evidence-ledger
```

正文证据 ID 使用内部锚点，例如 `<a href="#E03">〔E03〕</a>`；证据账本中的对应记录使用稳定 `id="E03"`。来源 URL、版本/commit、locator、supported statement、标签和访问状态全部保留。

### 5.3 自包含与离线要求

- CSS 全部内联；不依赖 CDN、Web font 或外部 stylesheet。
- 默认不使用外部 JavaScript；目录、折叠内容和返回行为优先使用原生 HTML。
- 模型流程图使用带 `<title>` 和 `<desc>` 的 inline SVG 或语义化 HTML flow，不依赖 Mermaid runtime。
- 公式使用 MathML、Unicode/HTML 或可读的等宽文本，不依赖 MathJax。
- 若用户明确调用 `sci-ai-figure` 并要求嵌入图片，图片使用 data URI 嵌入，以维持单文件合同；否则仅保留可折叠 figure brief。
- 所有论文、代码和外部证据链接可以指向网络，但打开本地文件和阅读正文不需要联网。
- 论文、代码和数据中的文本必须 HTML-escape；不允许复制来源中的 script、event handler、iframe 或可执行 markup。

### 5.4 可读性、可访问性与打印

- 桌面端使用正文 + 粘性目录；窄屏退化为单列，目录置于正文前。
- 正文宽度、字号和行距以长文阅读为优先，不使用仪表盘式高密度布局。
- 证据边界、作者主张和审查判断不能只靠颜色区分；同时使用文字标签和边框。
- `<nav>`、`<main>`、`<section>`、标题层级、表格表头和 `aria-label` 必须完整。
- 提供 `@media print`：隐藏粘性导航，以打印样式强制显示 `<details>` 内容，线性呈现必要元数据与证据账本，避免正文被交互布局截断。
- 浏览器 `Ctrl/Cmd+F` 应能检索全部正文与证据记录。

### 5.5 视觉语言与组件质量

UI 采用“科研出版物 + 长文阅读”风格，而不是后台仪表盘或通用 Markdown 预览器。实现阶段提供一个可复用 HTML 模板，保证不同论文具有一致的视觉质量。

- **色彩**：暖白或低饱和纸张色作为页面背景，深墨色正文，海军蓝/青绿色作为主强调色；警示与冲突使用克制的琥珀色/砖红色。所有正文和交互元素达到可读对比度，不使用大面积高饱和渐变。
- **字体**：只使用本地 system font stack。标题可使用本地 serif fallback 营造出版物层级，正文使用适合中英文混排的 sans-serif；代码、张量和配置使用 monospace。
- **版式**：桌面端目录约 240–280 px，正文最大宽度约 820–900 px；正文卡片不层层嵌套，段落之间保留足够呼吸空间。
- **标题区**：论文题目是唯一视觉主角；期刊、年份、DOI、mode/status 以低层级 metadata 呈现。作者主线、证据状态和审查入口三张卡在桌面端并排、窄屏纵向排列。
- **目录**：展示 01–08 编号、短标题和当前 target 状态；使用 `:target` 或最小内联脚本增强当前章节提示，但无脚本时仍完全可用。
- **正文组件**：统一提供背景提示、证据边界、实验卡、审查卡、公式/代码块、数据流、结论分级和 evidence badge。组件依靠标题、图标/符号、边框和文字共同表达语义，不只依赖颜色。
- **微交互**：锚点跳转平滑但尊重 `prefers-reduced-motion`；`details/summary` 有清晰 hover/focus 状态；外部链接与内部证据链接在视觉上可区分。
- **响应式**：在约 900 px 以下切换为单列，目录成为顶部可折叠区；表格允许横向滚动，不压缩到不可读。
- **打印**：去除阴影和装饰背景，保留标题层级、标签文字、URL 与证据关系；避免卡片或表格行在分页处被无意义截断。

模板不能为了“好看”隐藏关键证据、缩小正文、制造多栏正文或增加无信息价值的动画。视觉验收以连续阅读 15–20 分钟仍清晰舒适为准。

## 6. 证据与批判边界

单文件不等于弱化来源账本。证据账本作为 HTML 底部的可折叠一级组件，仍保留六种标签：论文、代码、外部核验、推断、缺失、冲突。

Sections 1–6 中的 conclusion-changing facts 使用中性证据边界：说明论文、代码、数据或外部材料分别显示什么，并指向 Section 7。Section 7 才评价替代解释、影响等级与最小解决实验。Section 8 不引入未经前文审查的新证据。

## 7. Standard 与 Audit 的内容边界

### Standard

- 八节主报告完整；
- 嵌入完整 evidence ledger；
- 只保留理解中心数据流和结论所需的形状、配置、实验与冲突；
- 最多三个可改变结论的外部 claim-family 核验；
- figure briefs 默认折叠且最多三个。

### Audit

- 保留同一主报告，不复制正文；
- 追加完整数据/训练审计、逐阶段模型接口、全实验矩阵和扩展批判审查；
- audit panels 引用主报告 section 和 evidence ID，避免第二份叙事。

## 8. 迁移范围

实现阶段需要同步修改：

1. `SKILL.md`：默认单 HTML、八节新标题、无独立阅读导航。
2. `references/output-contract.md`：HTML 文件合同、页面结构、证据锚点、standard/audit 边界。
3. `references/ai-ml-reading-guide.md`：Section 1–8 的新职责与相邻边界。
4. `references/evidence-policy.md`：单文件 ledger 与内部链接规则。
5. `tests/sci-read-paper/evals.json` 与 rubrics：新增 HTML、章节职责、任务/代理/机制区分和单文件要求。
6. `tests/test_sci_read_paper.py`：更新文件数、固定标题、HTML 自包含、锚点完整性和模式测试。
7. SiamProm 完整示例：用现有证据重写为单一 HTML，不重新检索论文；新 HTML 通过内容检查后，移除当前示例目录中的 `deep-reading.md` 与 `evidence-ledger.md`，Git 历史仍保留旧版本。

## 9. 验证策略

### 合同测试

- Standard 与 audit 各只声明一个 `.html` 输出。
- 八个 section ID、标题和顺序固定。
- 不存在独立 `阅读导航` section。
- Sections 1–8 的职责关键词和解释/批判边界存在。
- evidence ledger、figure briefs 和 audit panels 位于规定区域。

### HTML 结构测试

- 存在 doctype、`html/head/body`、header、nav、main 和 footer。
- 目录中每个锚点都解析到真实 section。
- 每个正文 evidence link 都解析到唯一 ledger ID。
- 不存在外部 stylesheet、script、font 或非 data-URI 图片资源。
- standard 示例不存在 audit-only panels；audit fixture 覆盖四个 audit panels。
- `complete|partial`、论文版本、代码 commit 和访问状态可定位。

### 内容回归

- SiamProm Section 1 明确预测目标是 promoter/non-promoter 序列分类，TSS 只是正样本采样锚点。
- Section 1 遵守背景 → 进展 → 不足 → 作者切入。
- Section 3 每项设计形成 problem → hypothesis → design → intended effect。
- Section 4 与 Section 5 共同跟踪同一具体样本，但不重复职责。
- Section 6 区分实验观察和作者解释，不提前给最终裁决。
- Section 7 保留现有 HIP1、phantom、split、IND 和 reproducibility 审查深度。
- Section 8 同时给出真实贡献、最终可信边界和最小下一步。

### 人工验收

- 浏览器离线打开，正文、目录、折叠 ledger 和内部链接可用。
- 桌面与窄屏均可连续阅读。
- 打印预览不截断正文和证据表。
- 读者无需打开第二个文件即可理解论文并核查任一 evidence ID。

## 10. 成功标准

- 每篇论文默认只产生一个可离线打开的 HTML 文件。
- 开头不再出现正文式“阅读导航”，但论文主线、证据状态和审查入口仍一眼可见。
- 八节之间没有职责重叠：背景、地图、设计逻辑、数据训练、模型流、实验、审查和综合各回答一个问题。
- 读者能够先理解作者，再集中审查作者，而不会在前六节反复被结论打断。
- 所有证据均能从正文 ID 跳转到同一文件中的来源记录。
- 单文件输出没有削弱 standard/audit 模式、paper-code 核查或蛋白质/小分子领域有效性要求。

## 11. 非目标

- 构建通用网页应用、服务器或数据库。
- 默认生成图片或调用 `sci-ai-figure`。
- 用视觉效果替代论文解释和证据核查。
- 在 standard 模式中嵌入全部代码接口、配置字段和次要实验。
- 重新检索或重新审计已经完成的 SiamProm 证据。
