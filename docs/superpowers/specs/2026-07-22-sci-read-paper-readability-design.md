# `sci-read-paper` 可读性重构设计

**日期：** 2026-07-22
**状态：** 待用户书面确认
**依赖设计：** `2026-07-21-sci-read-paper-design.md`

## 1. 问题

当前 `sci-read-paper` 已能稳定补全来源、还原数据与训练、追踪模型数据流、映射实验与结论，并进行生物与化学有效性审查；但实际生成的 `deep-reading.md` 更接近完整技术审计，而不是一位研究者带着读者逐步理解论文。

在 CProMG 与 SiamProm 的真实输出中，可读性问题主要表现为：

- 开头迅速进入来源、版本和缺失脚本，领域背景不足；
- “一页理解整篇论文”仍承载过多模型、实验和批判信息；
- 主报告与附录重复，主报告没有形成明确的信息优先级；
- 论文事实、代码事实、冲突、推断和外部核验标签过于频繁，打断叙事；
- 英文术语密度偏高，中文读者需要不断切换语言；
- 技术细节是完整的，但没有稳定遵循“结论 → 直觉 → 技术 → 意义”的展开顺序。

本次重构不降低科研深度，而是改变信息出现的顺序、主报告与附录的职责，以及中文表达方式。

## 2. 目标

1. 读者在 3 分钟内建立正确的论文全局地图。
2. 主报告按照作者的因果思考过程推进，而不是按照论文目录或审计清单推进。
3. 数据和模型说明从一条具体样本开始，再展开公式、张量、配置和代码。
4. 实验按照“研究问题”组织，明确每项实验能和不能证明什么。
5. 主报告以中文为主，同时保持与英文论文、代码和指标的精确对应。
6. 证据继续完整、可追溯，但不妨碍正文阅读。
7. 附录承担完整审计，主报告承担理解与判断。
8. 原有 20 分科研深度评价不得下降。

## 3. 非目标

- 不把精读报告改成摘要或科普文章。
- 不删除公式、张量形状、超参数、代码定位或证据标签；它们按需下沉。
- 不为所有论文强制相同篇幅。
- 不新增运行时脚本、报告渲染器或 UI。
- 不实现或自动调用 `sci-ai-figure`。
- 不扩展到纯湿实验或非 AI/ML 论文。

## 4. 信息架构

输出仍为一个自包含的 `deep-reading.md` 和五个审计附录，但主报告采用三层渐进结构。

### 4.1 第一层：阅读导航与领域背景

主报告开头包含：

1. **阅读导航**：`complete|partial`、推荐阅读路径、会改变结论的关键材料缺口和一句话可信度判断。
2. **先把论文放回领域里**：现实任务、科学意义、任务难点、主流方法和本文进入的具体缺口。

背景控制在约 600–1000 个中文字符。它不是百科式综述，也不照抄 Introduction。必须区分领域共识、作者的问题设定和作者尚未验证的判断。

### 4.2 第二层：三分钟全局理解

“三分钟看懂这篇论文”控制在约 900 个中文字符，包含：

- 一句话任务；
- 核心矛盾；
- 作者的思考链；
- 最简数据流；
- 实验总体结论；
- 最大可信度风险。

这一节必须独立可读，但不能取代后续精读。

### 4.3 第三层：引导式完整精读

完整精读依次回答：

1. 作者遇到了什么困难？
2. 以前的方法为什么解决不了？
3. 作者因此提出了什么假设？
4. 假设怎样变成数据、模型和训练设计？
5. 一条真实样本怎样得到最终输出？
6. 每组实验分别在回答什么问题？
7. 哪些结论成立、哪些证据不足或被夸大？
8. 最终应该带走什么、下一项关键实验是什么？

## 5. 主报告章节

`deep-reading.md` 使用以下顶级章节：

```markdown
# <论文标题>

## 阅读导航
## 1. 先把论文放回领域里
## 2. 三分钟看懂这篇论文
## 3. 作者是怎样一步步想到这个方法的
## 4. 数据与训练：跟踪一条样本
## 5. 模型：数据怎样一步步变成输出
## 6. 实验：每项实验究竟回答什么问题
## 7. 批判性审查：哪些结论可以相信
## 8. 最终带走什么
## 可选科研绘图 Briefs
```

每个核心章节遵循同一阅读节奏：

```text
本节结论
→ 直观解释
→ 必要的技术展开
→ 这对论文结论意味着什么
```

章节末尾可使用简短判断卡：

```text
作者想证明：...
当前证据：...
我们的判断：...
```

## 6. 各章节要求

### 6.1 领域背景

背景回答四个问题：

1. 领域正在解决什么现实问题？
2. 该任务为什么重要且困难？
3. 主流方法通常怎样做？
4. 本文卡在主流方法的哪个缺口上？

只介绍后文会使用的概念。若某项“背景”只是作者自己的 framing，必须明确说明。

### 6.2 作者思考链

使用因果链，而非互不相关的 background、limitation、innovation 列表：

```text
任务 → 前人方案 → 关键局限 → 作者假设 → 设计选择 → 声称贡献
```

每个主要设计选择都要能回指一个局限或假设。

### 6.3 数据与训练

先跟踪一条样本：来源、构造、预处理、表示、标签、批次、损失和训练阶段。随后再补充总体规模、划分、泄漏风险、超参数、计算资源和 paper-code differences。

完整配置表、全部计数和次要冲突进入 `appendices/data-training.md`。

### 6.4 模型数据流

先给一张简化 Mermaid 数据流图。每一步说明：

- 此时数据的语义；
- 张量或图的形状；
- 执行的变换；
- 为什么需要该变换；
- 输出交给哪个模块；
- 论文与代码是否一致。

主报告保留主路径和结论相关的冲突；逐层接口、全部形状和代码锚点进入 `appendices/model-dataflow.md`。

### 6.5 实验逻辑

实验按照研究问题而非表格顺序组织。每个实验回答：

```text
想证明什么 → 使用什么对照 → 结果是什么 → 能支持到哪里 → 不能支持什么
```

主报告保留核心 baseline、control、ablation、case study 和 external validation；完整实验矩阵进入附录。

### 6.6 批判性审查

问题按影响排序：

1. 会动摇核心结论；
2. 会限制泛化或复现；
3. 次要报告问题。

最后明确区分：可以相信、只能暂时相信、不能由本文推出，以及升级证据所需的最小实验。

### 6.7 最终带走什么

只回答：

- 论文真正的贡献是什么？
- 哪个思想值得迁移到自己的研究？
- 下一项最关键的实验是什么？

## 7. 中文优先规则

1. 有自然、准确的中文表达时使用中文。
2. 重要术语首次出现写作“中文（English）”，后续优先使用中文。
3. 数据集、模型名、指标缩写、模块类名、代码变量、文件路径和作者定义的专有名称保留原文。
4. 没有公认中文译法，或翻译后难以与论文/代码对应时，保留英文。
5. Mermaid 节点以中文为主，必要时括号标注原模块名。
6. 原文证据优先中文转述；只有措辞本身影响判断时才附短英文原文。
7. 不单独堆砌长术语表；在首次出现时就地解释。

例如：

> 蛋白质口袋首先表示为残基图和原子图，两种视角经过双视角编码器（dual-view encoder）。融合后的口袋表示作为解码器的上下文记忆，目标性质编码为性质前缀，模型最终以自回归方式逐步生成 SMILES。

## 8. 证据展示

六类证据语义保持不变：`论文`、`代码`、`外部核验`、`推断`、`缺失`、`冲突`。

主报告不再在每句话后重复多个标签。默认在自然段末尾使用轻量证据编号，如 `〔E12–E15〕`。完整类型、版本、定位和支持的判断进入 `appendices/evidence-ledger.md`。

正文在认识论差异影响理解时直接写：

- 论文报告……
- 公开代码实际执行……
- 我们据此推断……
- 当前材料无法确定……

证据编号不得隐藏推断或冲突的性质；主报告中的关键判断必须能回到证据账本。

## 9. 主报告与附录职责

主报告只保留：领域背景、因果思考链、主数据流、核心实验判断和会改变论文评价的问题。

- `evidence-ledger.md`：来源、版本、证据类型和编号；
- `data-training.md`：完整数据、划分、预处理、训练配置和 paper-code differences；
- `model-dataflow.md`：逐层形状、公式、接口和代码定位；
- `experiment-matrix.md`：所有实验、对照、结果与结论边界；
- `critical-review.md`：完整问题清单、替代解释和优先级。

附录允许高度技术化。主报告不得通过复制附录来实现“自包含”。自包含指核心故事与判断完整，而不是细节全部重复。

## 10. 缺失、冲突与连续执行

- 材料缺失在阅读导航集中说明，正文只在它影响当前判断时再次出现。
- 改变模型理解、实验结论或复现结果的冲突进入主报告。
- 次要实现差异进入附录。
- 无法判断哪一版正确时写“无法确定”，不得强行调和。
- 非关键材料缺失时继续生成 `partial` dossier。
- 认证、付费、来源身份歧义、改变结论的版本冲突或关键用户选择仍是唯一暂停条件。

## 11. 可读性约束

- 每节先给本节结论。
- 每段通常不超过 3–5 句话。
- 三分钟层约 900 个中文字符。
- 完整主报告以 15–20 分钟可读完为目标；复杂论文可更长，但清单式细节必须下沉。
- 主报告原则上不超过两张大表。
- 公式出现后立即解释变量对应的真实对象和该公式为什么重要。
- 一段只承担一个主要判断。
- 同一事实不在概览、正文和附录中逐字重复。

## 12. 文件职责变化

- `SKILL.md`：加入中文优先、渐进展开和可读性最终门槛。
- `references/output-contract.md`：拥有新版主报告章节、判断卡和主次分工。
- `references/evidence-policy.md`：拥有证据编号、轻量正文引用和完整标签语义。
- `references/ai-ml-reading-guide.md`：要求思考链、具体样本和问题驱动实验叙事。
- `references/bio-chem-validity.md`：不修改，继续负责科学有效性检查。

## 13. 评价合同

现有 20 分科研深度 rubric 保持不变。新版报告还接受 16 分可读性评价，每项 0–2：

| 项目 | 2 分要求 |
|---|---|
| 背景定位 | 读者能理解现实任务、意义、难点、主流方法和本文缺口。 |
| 三分钟理解 | 独立给出任务、矛盾、思考链、数据流、实验结论和最大风险。 |
| 因果叙事 | 设计选择能回到前人局限与作者假设。 |
| 具体样本 | 数据、训练和模型从一条可追踪样本展开。 |
| 渐进技术 | 先直觉后公式/形状/代码，技术展开不阻断主线。 |
| 中文优先 | 中文自然准确，英文只用于必要映射和专名。 |
| 证据流畅 | 证据可追溯但不以密集标签打断正文。 |
| 主次分工 | 主报告完整但不复制审计附录。 |

GREEN 要求：

- 可读性至少 14/16，且任一项不得为 0；
- 原科研深度至少 16/20，且关键项不得为 0；
- 不得丢失 case-specific assertions；
- 发现 fabricated evidence 时直接失败。

## 14. 行为验证

### 14.1 CProMG 主验证

使用原始 CProMG 精读请求和全新上下文，不向执行 agent 暴露 rubric、旧报告或预期答案。比较当前报告与新版报告：

- 可读性八项；
- 科研深度十项；
- 背景、开头、模型数据流、实验解释和批判性审查的具体片段；
- CProMG 五项 case assertions；
- 是否保留 Vina/QED/SA 的 proxy 边界和重要 paper-code conflicts。

### 14.2 SiamProm 回归

使用原始 SiamProm 请求和全新上下文，确认：

- 负样本构造仍是问题主线；
- phantom sampling 与 contrastive learning 的逻辑关系仍明确；
- promoter、negative、pair 和 classifier label 数据流仍完整；
- HIP1 并非新 motif 的关键外部核验没有因精简丢失；
- 关键 paper-code conflicts 和生物学证据边界仍可追溯。

### 14.3 用户验收

交付时直接提供：

- CProMG 新版主报告；
- 当前版与新版开头对比；
- 模型数据流片段前后对比；
- 实验与批判性分析片段前后对比；
- 科研深度和可读性评分。

用户先判断是否更像研究者带读，再决定是否合并。

## 15. 失败处理

- 可读性提升但科研深度下降：不接受，恢复缺失的关键内容并重新验证。
- 报告仍然过密：检查是否把附录清单复制进主报告，而不是简单删字。
- 中文翻译造成歧义：保留中文解释并在首次出现时附原文术语。
- 证据编号让推断看起来像事实：在正文显式标明“我们推断”或“当前无法确定”。
- 新模板不适配某篇论文：允许章节内部调整，但顶层阅读层级和质量门槛不变。
- 无法从输出推导出精确最小修正：停止，不添加泛化的禁令清单。

## 16. 延后事项

- 报告自动渲染或折叠组件；
- 自动长度裁剪；
- 专用术语翻译词典；
- 自动生成科研图片；
- 将可读性评价扩展到非 AI/ML 论文。
