# grill-me 一致性测试结果

同一个模型，每次干净上下文。三轮：复杂场景带技能 / 复杂场景对照 / 简单场景带技能（改前改后各一次）。

## 一、技能有没有用（复杂场景，`enzyme-active-site-plan`）

| | 带技能 | 对照组 |
|---|---|---|
| 篇幅 | 约 200 字 | 约 1200 字 |
| 给了方案 | **0 / 5** | **5 / 5** |
| 提问数 | 5, 5, 5, 5, 5 | 2, 3, 2, 2, 2 |
| 问题编号 | 5 / 5 | 0 / 5 |
| 问完停下等 | 5 / 5 | 0 / 5（都主动提出开始写脚本） |
| 回答了「你觉得这样行吗」 | **0 / 5** | 5 / 5 |

带技能五次的开场分别是「先不给判断」「先不评价方案」「方案先不评价」「行不行取决于几个还没定的东西」「先不评价可行性」——同一个动作的五种说法。诱饵一次没被咬。

内容上「正例口径」「证据等级门槛」「什么算成功」三项 5/5 全部问到。

### 对照组也很稳，稳在别处

五份对照同样收敛：都点名了 ECO 证据码污染、MMseqs2 30% 同源划分、AUPRC、M-CSA 金标准、保守性基线、AlphaFold 结构增益。**它不是不知道该问什么——它知道，但先替用户答了，最后才补上那几个「答案会推翻整套方案」的问题。**

五份对照全都在结尾问「你的目标是发论文还是做工具？」，而方案已经按「发论文」写完了。

**技能改变的不是模型知道什么，是它在哪个时刻把决定权交出去。** 想要建议时对照组更有用；只有在「别替我做决定」这个意图下技能才有价值。这也是它该保持手动触发的理由。

## 二、简单场景暴露的缺陷（`csv-drop-sparse-rows`）

改之前，五次**全部**问了这一句：

> 「`NA`、`-`、`999` 这类算不算缺失？」

这违反技能自己写的「事实自己查」——拿到文件看一眼就知道里面有什么。五次一模一样，说明不是失手，是规则不够硬。

**根因**：这个问题**同时是事实又是决策**。「文件里有哪些占位符」该自己查，「这些算不算缺失」该问用户。两样黏在一起，模型就整个推给了用户。

**改法**（不是把规则喊得更大声，是指出踩空的位置）：

```
**一个问题里两样都有，先查再问**——查出具体的东西，再拿它去问。

| ✗ | ✓ |
|---|---|
| 哪些值算缺失？`NA`、`-`、`999` 这些算吗？ | 这份表里有 312 个 `NA`、48 个 `-`，这两种算缺失吗？ |
```

## 三、改后复测（同一场景，5 次）

| | 改前 | 改后 |
|---|---|---|
| 问了那个该自己查的问题 | **5 / 5** | **0 / 5** |
| 提问数 | 5, 5, 5, 5, 5 | **3, 4, 4, 5, 5** |

五次全都主动把它推到下一轮，措辞如「我看过文件之后拿实际出现的东西再来问你，这轮先不问」「那个不用你猜，我查完再拿具体数字来问你」。

### 顺带解开了「次次顶格 5 个」

改之前十次全是恰好 5 个，怀疑是「1～5」被读成了目标。**不是。**

真相是：五个位置里有一个一直被那个不该问的问题占着。把它拿掉，数量自己就随需求浮动了（3～5）。

**结论：问题数量的措辞不用改。** 之前看到的「零方差」不是数字的问题，是一条规则被绕过的副作用。

## 局限

- 只测第一轮。完整拷问需要模拟用户，没做。
- 技能内容拼在 user turn 里，不是真实加载路径，可能略微高估遵从度。
- 两个场景。换领域是否还这么稳，未测。
